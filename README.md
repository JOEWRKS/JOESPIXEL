# JOESPIXEL

사용자 원본을 고정 격자·팔레트의 픽셀 아트로 제작하고 저장본을 검수하는 Codex 스킬입니다. 스킬 호출 이름은 **`joewrks-pixel-art`**, 현재 버전은 **2.23.0**입니다.

원화 생성에는 Codex에서 사용 가능한 이미지 도구가 필요합니다. 포함된 Node 코드는 관찰 입력에 따른 변환·검증을 수행합니다. 눈·피부·머리·선의 의미를 자동으로 알아내거나 시각 품질을 보장하는 엔진은 아닙니다.

## 설치

Node.js 20 이상과 Git이 필요합니다. 기존 스킬 폴더가 있다면 덮어쓰기 전에 별도로 백업합니다. 아래는 새 설치 기준입니다.

```powershell
git clone https://github.com/JOEWRKS/JOESPIXEL.git "$HOME/.codex/skills/joewrks-pixel-art"
Set-Location "$HOME/.codex/skills/joewrks-pixel-art"
npm ci --ignore-scripts
npm test
```

Codex에서 새 대화를 열어 스킬을 불러옵니다. 프로젝트 계약이 더 엄격하면 그 계약과 현재 사용자 지시를 우선합니다. 의존성은 기존 변환기가 사용하는 `pngjs@7.0.0` 하나입니다.

## Codex에서 사용

원본 이미지와 원하는 콘셉트를 함께 전달합니다.

```text
$joewrks-pixel-art
이 원본으로 처음부터 만들어줘. 캔버스는 1024×1024, 팔레트는 첨부 JSON으로 고정.
픽셀 크기는 실제 후보 이미지로 비교해서 선정하고, 전체 1도트 외곽선과
이목구비·손의 주요 면·틈이 함께 살아나는지 확인해.
초안·최종 저장본을 직접 비교하고 수동 덧칠은 하지 마.
```

크기를 지정하려면 `한 도트는 8×8 표시 픽셀, native는 128×128로 고정`처럼 캔버스와 논리 격자를 함께 명시합니다. `픽셀 2배`는 도트 한 변 2배/논리 가로·세로 칸 수 절반을 뜻하며, 단순 화면 확대와 구분합니다. 고정 크기에 필수 형태가 들어가지 않으면 임의로 크기를 바꾸지 않습니다.

기존 결과를 수정할 때는 원본·초안·최신 기준본과 문제 부위를 지정합니다. 재변환과 원화부터 새 생성은 서로 다른 작업입니다.

## 7단계

| 단계 | 저장·확인할 내용 |
| --- | --- |
| 1. 캐릭터화 | 실제 원본, 허용 변화, 캔버스, 팔레트와 역할, 필수 형태 |
| 2. 크기 선정 | 같은 캐릭터화본의 서로 다른 격자 후보, 외곽선 마스크, 병목 부위 비교 |
| 3. 픽셀 설계 | 선택 격자에서 읽히는 초안 |
| 4. 재질·경계 배정 | 원본 관찰 영역, 눈 소유 영역, 재질 배정표와 구분 PNG, 충돌 검수 |
| 5. 격자 배치 | 하나의 격자에서 면과 1도트 선을 함께 배치한 PNG |
| 6. 손실 수정 | 최초 손실 단계의 공용 처리 수정, 정상 영역 보존 확인 |
| 7. 시각 검수 | 원본·초안·기준본·저장본의 전체 및 부위별 직접 비교 |

자세한 통과 조건은 [제작 절차](references/workflow.md), 파일 필드는 [입력 계약](references/input-contract.md)에 있습니다. 규칙을 JSON에 적었다는 사실만으로 코드에서 모든 의미·품질을 검사하는 것은 아닙니다.

## 변환 명령

스킬 폴더를 작업 디렉터리로 사용합니다. `job.json`과 그 파일이 가리키는 계약·원본·배정표·단계 증거를 **실제 관찰로 먼저 준비**해야 합니다. 이미지 생성이나 관찰을 건너뛰는 단일 자동 명령은 제공하지 않습니다.

```powershell
npm run pixel -- prepare /absolute/path/job.json /absolute/path/new-run
npm run pixel -- finalize /absolute/path/new-run /absolute/path/review.json
npm run pixel -- verify /absolute/path/new-run
```

Windows에서는 `D:/art/job.json`처럼 절대 경로를 사용할 수 있습니다.

- `prepare`: 후보 PNG와 `review.pending.json`을 생성합니다. 이때 `delivery/`는 없습니다.
- 직접 저장 PNG를 확인한 뒤 별도 `review.json`에 관찰과 증거를 기록합니다. `UNVERIFIED`를 일괄 `PASS`로 바꾸면 안 됩니다.
- `finalize`: 단계·입력 해시·팔레트·격자·실제 선·검수 기록을 확인하고 변환을 재실행하여 출력 일치를 검사합니다. 통과한 경우에만 `delivery/native.png`, `delivery/display.png`, `receipt.json`을 저장합니다.
- `verify`: 납품본과 검수·코드·입력 결속을 다시 확인합니다. 코드나 입력을 바꾸면 새 실행이 필요합니다.

`READY_FOR_USER_REVIEW`는 검수 기록과 기술 검사를 통과했다는 뜻입니다. 자동 시각 인식이나 사용자 채택을 의미하지 않습니다. 저수준 모듈의 후보 출력은 납품 완료본이 아닙니다.

## 파일 구성과 유지보수

- `SKILL.md`: 작업 시 항상 적용할 간결한 지침.
- `references/workflow.md`: 현재 7단계 절차.
- `references/input-contract.md`: 실행 입력과 저장본 검수 사용법.
- `references/workflow-rules.json`: 규칙 목록과 검사 범위. 실행 구현은 `scripts/`가 담당합니다.
- `scripts/`: 현재 변환 경로, 공용 기하·색면 연산, 회귀 시험. 내부 후보 연산은 정식 실행 경로가 아닙니다.
- `agents/openai.yaml`: Codex 표시 이름과 기본 호출문.

`npm test`는 합성 이미지와 변조 사례로 기계적 조건을 검사합니다. 실제 작업은 추가로 저장 PNG를 직접 검수해야 합니다. 생성 이미지, 개별 캐릭터 관찰표, 작업 이력, 출력 폴더는 저장소에 포함하지 않습니다.

2.23.0은 2.22.6의 현재 변환을 패키지로 정리한 버전입니다. 과거 예시 이미지·누적 문서·미사용 보정 경로를 제거하고, 실행하지 않은 검사와 구형 제작 경로가 납품을 통과하지 못하도록 했습니다. 옛 5·6단계 기록은 조사 목적으로만 읽을 수 있으며 신규 제작은 7단계만 허용합니다. 이전 납품 영수증을 새 코드에 맞춰 덮어쓰지 않습니다.

## 2.23.0 정리 검증

- 재실행 가능한 검사: `npm ci --ignore-scripts`, `npm test`의 13개 시험 파일, 전체 JavaScript 구문 검사, 스킬 형식 검사.
- 로컬 실제 이미지 비교: 도로롱 128×128·256×256, 도로시, 카리나의 동일 입력 재변환 4건 모두 이전 PNG와 바이트까지 일치(변경 픽셀 0). 격자·팔레트·실제 선 검사도 통과. 새로운 시각 품질 개선을 주장하는 결과가 아니다.
- 실제 캐릭터 원본·관찰표·비교 이미지는 이 저장소에 게시하지 않았다. 위 실제 이미지 비교는 로컬 증거이며, 저장소만으로 재실행 가능한 시험은 합성 회귀 시험이다. 선언된 선 영역 밖의 완전성은 자동 보증하지 않는다.
